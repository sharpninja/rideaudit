# Client contracts use src/RideAudit.Protos

The interim companion proto (`interim/rideaudit/v1/custody.proto`, namespace `RideAudit.V1`) has been removed. Avalonia clients bind to the authoritative messages generated by `RideAudit.Protos` (contract version 0.4.0).

| Keep | Now |
| --- | --- |
| `ISealedAdmissionClient` | Methods take `SubmitSealedRequest` / `GetAdmissionStatusRequest` and return `AdmissionDecision` from `RideAudit.Protos.Admission.V1` |
| UI views and view models | Unchanged. They do not reference generated client classes |
| `SubmissionMapper` | Maps the device `CustodyReceipt` into `ReceiptCore` and `AttestationSubmission` |
| `ContractProvenance.Source` | `src/RideAudit.Protos` |

`InterimInProcessAdmissionClient` is still a client preflight. It does not call server admission, does not decrypt, and does not set `admitted`. The anchor envelope stays pending with `live_bitcoin_metadata` false and no transaction reference or block height.

`GrpcSealedAdmissionClient` is the generated gRPC path. `CaptureAdmissionChannel` constructs it when `RIDEAUDIT_ADMISSION_ADDRESS` and a bearer are set, and fail-closes when they are not. Production capture uses `CanonicalAdmissionRequestFactory` with `RIDEAUDIT_TENANT_ID`, `RIDEAUDIT_DRIVER_ID`, and raw Play token material. Dual-phone tests may inject `ServerAdmissionRequestFactory` (fixture.v1. token, enrolled tenant, `ReceiptCoreCodec`) and an in-process HSM escrow deposit. That fixture inject is not the production composition. Server admission accepts the device RAES bytes when the submitted `ReceiptCore` binds the SHA-256 of those bytes and the fixture attestation, escrow, and chain checks pass. Those checks use the documented server fixtures (`fixture.v1.` tokens and `documented-fixture` anchors) unless a live calendar/RPC URL is configured. They are not live Play Integrity JWTs. Live calendars never invent a Bitcoin or L2 transaction id.

Device envelopes remain the client RAES layout in `RideAudit.Client.Seal`. This path does not re-encode them into the server `RIDESEAL1` envelope. `SubmissionMapper` still puts the device SHA-256 hex in `AttestationSubmission.token`. That hex is not a server `fixture.v1.` token. A fixture admission test supplies the server fixture token separately. The device package identity (`org.rideaudit.app`) and the server allowlist (`app.rideaudit.capture`) stay distinct.

Do not copy server admission, counsel, chain, escrow, or ingest implementations into this project.
