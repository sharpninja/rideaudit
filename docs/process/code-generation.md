# Code-generation procedure

**Author:** Sharp Ninja
**Status:** Process rule

This procedure applies whenever an agent generates code or code-like project artifacts. It is a documentation and review rule; it does not authorize changing application scope.

## Allowed generation

Use only one of these approved generator configurations:

- Grok `grok-4.6-xhigh`.
- GPT Sol family at `xhigh` (`gpt-5.6-sol`; family name `gpt-6-sol`).

Record the actual agent, provider, model, and reasoning setting. Do not infer or invent model metadata after the fact.

## Required opposing review

Immediately after generation, send the complete relevant change and context to the opposing configuration for hostile validation. The opposing configuration is mandatory:

- Generated by Grok `grok-4.6-xhigh` -> validate with Codex / GPT Sol family at `xhigh` (`gpt-5.6-sol`; family name `gpt-6-sol`).
- Generated by GPT Sol family at `xhigh` (`gpt-5.6-sol` / `gpt-6-sol`) -> validate with Grok `grok-4.6-xhigh`.

Dated amendment 2026-09-28: `gpt-6-sol` aliases to the available Sol-family model `gpt-5.6-sol` at reasoning xhigh. See [hostile-validation.md](hostile-validation.md).

The generator cannot serve as its own HV validator. HV must challenge the generated result rather than merely restate it, including security, correctness, requirements coverage, custody, and fail-closed behavior as applicable.

## Capture and commit immediately

Retain every HV request and response as an exact JSON pair. Immediately when the response arrives:

1. Save the pair as a unique timestamp-plus-topic filename under `docs/reviews/hv-pairs/`.
2. Include the required `request`, `response`, `generator`, `validator`, and `committed_at` members.
3. Commit the pair before relying on the validation or accepting the generated change.

The pair-file example and naming rules are specified in [hostile-validation.md](hostile-validation.md). Summaries, screenshots, or a chat transcript without the JSON pair are not sufficient evidence.

## Authentication boundary

Docs-only HV through ChatGPT-authenticated Codex cannot use `gpt-6-sol` until API-key authentication is configured. Until then, do not invent a completed HV run, do not label an unavailable attempt as passed, and do not substitute same-model review. Record an unavailable or failed attempt truthfully if it is retained.

## Completion checklist

- [ ] Generator is Grok `grok-4.6-xhigh` or GPT Sol family at `xhigh` (`gpt-5.6-sol` / `gpt-6-sol`).
- [ ] Opposing agent/model was selected from the mandatory matrix.
- [ ] Full request and response were retained without rewriting.
- [ ] Pair was saved under `docs/reviews/hv-pairs/` with a timestamp and topic slug.
- [ ] Pair was committed immediately upon response receipt.
- [ ] Authentication limitations and any failed/unavailable status are stated truthfully.

No application code is changed by this documentation rule.
